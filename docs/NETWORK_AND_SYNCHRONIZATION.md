# Сеть и синхронизация

## 1. Авторитет сервера

Сервер подтверждает:

- попадания;
- урон;
- здоровье;
- смерть;
- ресурсы;
- покупки;
- награды;
- состояние контрольных точек;
- результат матча.

Клиентские данные рассматриваются как запросы, а не как достоверные факты.

## 2. Проверка RemoteEvent и RemoteFunction

Каждый удалённый вызов должен проверять:

1. Типы входных данных.
2. Структуру данных.
3. Допустимые диапазоны чисел.
4. Принадлежность объекта игроку или его команде.
5. Текущее состояние матча.
6. Наличие права выполнить действие.
7. Частоту запросов.
8. Защиту от спама и повторных запросов.

Ошибочные запросы не должны менять игровое состояние.

## 3. Синхронизация боя

Необходимо согласованно передавать состояние:

- отрядов;
- отдельных бойцов, если они находятся в зоне детальной симуляции;
- контрольных точек;
- приказов;
- результата боя;
- состояния матча.

Для массовых столкновений необходимо выбирать минимально достаточную частоту обновления.

## 4. Уровни детализации

Дальние отряды могут рассчитываться упрощённо.

Ближние отряды могут использовать более детальную симуляцию.

Переход между уровнями детализации не должен давать одной стороне несправедливое преимущество.

## 5. Открытые вопросы

- Частота обновления разных типов состояния.
- Радиусы переключения детализации.
- Интерполяция движения на клиентах.
- Поведение при потере пакетов.
- Поведение при кратковременном отключении.
- Допустимые задержки командования.
