# Тестирование и производительность

## 1. Цели

Производительность должна измеряться на реальных игровых сценариях, включая массовые столкновения.

Целевой ориентир — около 60 FPS на ПК. Это не гарантия до проведения тестов.

Мобильные устройства также входят в целевые платформы. Для них необходимо определить отдельные минимальные характеристики.

## 3. Этапы разработки

### P0 — тестовый стенд

Необходимо реализовать:

- движение NPC;
- простой бой;
- телеметрию;
- воспроизводимые нагрузочные сценарии.

### P1 — боевой прототип

Необходимо реализовать:

- отряды;
- базовые приказы;
- выбор целей;
- урон и смерть;
- заглушку морали.

### P2 — минимальный матч

Необходимо реализовать:

- три контрольные точки;
- игроков и ботов;
- ресурс;
- респаун;
- завершение матча.

### P3 — метаигра

Необходимо реализовать:

- лобби;
- сохранение;
- исследования;
- конфигурации армии;
- награды.

### P4 — расширение

Необходимо реализовать:

- военные культуры;
- построения;
- интерфейс;
- балансировку.

## 4. Метрики

В первых измерениях необходимо определить:

- загрузку CPU сервера;
- использование памяти сервера и клиента;
- частоту кадров;
- задержку команд;
- частоту сетевых обновлений;
- время поиска пути;
- время выбора целей;
- число активных NPC;
- частоту ошибок;
- количество зависших состояний.

Численные пороги устанавливаются после базовых измерений на целевых устройствах.

## 5. Критерии качества

- Отряд не должен бесконечно преследовать недоступную цель.
- Новый приказ должен корректно отменять предыдущее преследование.
- Смерть всех бойцов должна корректно завершать жизненный цикл отряда.
- Повторное развёртывание не должно обходить таймер и стоимость.
- Клиент не должен иметь возможности подделать урон, валюту или результат матча.
- Длительная сессия не должна приводить к накоплению неиспользуемых объектов.
- Подписки событий должны отключаться, когда больше не нужны.
- Массовый бой не должен приводить к критическому падению производительности.
