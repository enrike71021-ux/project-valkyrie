# Техническая архитектура Roblox

## 1. Основные принципы

- Сервер авторитетен для значимого игрового состояния.
- Клиент отвечает за ввод, камеру, интерфейс и визуальную обратную связь.
- Игровые системы разделяются на ModuleScript и сервисы.
- `_G` не используется.
- Не создаются монолитные скрипты, объединяющие все системы.
- Добавление новых культур и юнитов должно выполняться преимущественно через определения данных.

## 3. Ответственность сервера

Сервер принимает окончательные решения по:

- здоровью и смерти;
- попаданиям и урону;
- ресурсам и наградам;
- составу армии;
- развёртыванию отрядов;
- состоянию контрольных точек;
- завершению матча;
- покупкам;
- сохранённому прогрессу.

## 4. Ответственность клиента

Клиент отвечает за:

- ввод игрока;
- камеру;
- интерфейс;
- отображение чисел урона;
- отображение приказов;
- визуальные эффекты;
- стратегическую карту;
- отправку запросов на выполнение команд.

Клиент не должен сообщать серверу готовый результат действия.

Например, клиент может отправить запрос на атаку, но не может сообщить: «Я нанёс противнику 100 урона».

## 5. Масштабирование

Сначала необходимо создать нагрузочный тестовый стенд.

Нельзя заранее обещать конкретное количество NPC или гарантированную производительность без тестирования на целевых устройствах.
